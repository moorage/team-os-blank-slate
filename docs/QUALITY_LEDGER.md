# QUALITY_LEDGER.md

Purpose: make structural quality legible, track debt, and support small clean-up PRs.

Scoring scale:
- 5 = strong
- 4 = solid with minor gaps
- 3 = acceptable but notable debt
- 2 = fragile
- 1 = high risk / poor legibility

Last refreshed: 2026-05-07
Refresh owner: knowledge automation + reviewer of affected PRs

## Scorecard
- Architecture legibility: 4
- Boundary parsing / type discipline: 4
- Test strength: 4
- Reliability / observability: 4
- Security hardening: 4
- Documentation freshness: 5
- Operational simplicity: 4

## Evidence

- `docs/ARCHITECTURE.md`, `docs/KANBAN_SCHEMA.md`, and `docs/NATIVE_APPS.md` now describe the active Team OS boundaries and operator surfaces.
- `kanban/scripts/test/*.test.ts` covers validation, rendering, history, and standup behavior against the committed sample repository state.
- `swift test --package-path apps/native` covers repo-access gating, branch naming, mutation planning, and GitHub request construction for native write flows.
- `apps/native/TeamOSApps.xcodeproj` builds a real `TeamOSMacApp` and `TeamOSiOSApp` shell against the checked-in shared sources.
- root `package.json` now exposes `team-os:typecheck`, `team-os:test`, `team-os:validate`, and `team-os:render` so the harness can verify the new feature surfaces directly.

## Structural debt register

- The Apple shells expose repository access checks and sample Team OS state, but they do not yet drive end-to-end card mutations from the UI.
- The live GitHub path is transport-tested locally, but it is not yet smoke-tested against a real credentialed repository in CI.
- The checked-in Xcode project is generated by `apps/native/scripts/generate_xcodeproj.rb`, so source-layout changes still require disciplined regeneration.
- Root `lint` and non-Team-OS integration smoke commands remain harness placeholders and do not yet validate additional runtime surfaces.

## Improvement rules

- Increase architecture and security scores only when the native shells can execute a controlled end-to-end repository mutation smoke path.
- Increase operational simplicity only if future workflow additions preserve the current branch/PR-only write contract and deterministic render path.

## Maintenance rule
Do not manually inflate scores.
Adjust them only when the code, tests, or docs materially justify it.
